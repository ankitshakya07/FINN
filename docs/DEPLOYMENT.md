# FINN Production Deployment & Operations Guide

This document outlines the deployment architecture, configuration options, container setup, and operational procedures for **FINN** (Financial Investment Intelligence).

---

## 1. System Architecture

```text
       Mobile Device / Browser
                 │
                 ▼ (Port 3000)
    ┌──────────────────────────┐
    │     Next.js 15 PWA       │
    │  (TypeScript + App Router│
    │   Tailwind + Vanilla CSS)│
    └────────────┬─────────────┘
                 │ HTTP / REST & SSE (JSON)
                 ▼ (Port 8000)
    ┌──────────────────────────┐
    │     FastAPI Backend      │
    │  (Python 3.12 + Uvicorn) │
    └────────────┬─────────────┘
                 │
                 ▼
    ┌──────────────────────────┐
    │     SQLite Database      │
    │     (`finn.db`)          │
    └──────────────────────────┘
```

### Core Services:
- **Frontend PWA**: Next.js 15 App Router running standalone on port 3000. Provides the mobile-first dashboard (Brief, Ask AI, Watch & Signals, Research Hub).
- **Backend API**: FastAPI running on port 8000 with streaming SSE endpoints (`/research`), multi-turn query parsing (`/ask`), and SQLite-backed primary evidence repositories.
- **Data Layer**: Embedded SQLite (`backend/finn.db`) with automatic table creation and idempotent fixture loading (`company_fundamentals`, `company_commitments`, `ask_messages`, `prices`, `announcements`).

## 2. Environment Variables

Create `.env` based on `.env.example`:

| Variable | Description | Default |
|---|---|---|
| `APP_ENV` | Environment mode (`development` or `production`) | `production` |
| `DEMO_MODE` | Whether to operate using offline verified fixtures | `true` |
| `DATABASE_URL` | SQLite database URI | `sqlite:///./finn.db` |
| `CORS_ORIGINS` | Comma-separated allowed frontend origins | `http://localhost:3000,http://127.0.0.1:3000` |
| `NEXT_PUBLIC_API_BASE_URL` | Public API endpoint for frontend requests | `http://localhost:8000` |
| `LLM_BASE_URL` | OpenAI-compatible chat completions endpoint | `https://api.openai.com/v1` |
| `LLM_API_KEY` | Optional LLM provider API key | `""` |
| `LLM_SMALL_MODEL` | Classification model | `gpt-4.1-mini` |
| `LLM_STRONG_MODEL` | Synthesis & reasoning model | `gpt-4.1` |

## 3. Deployment Methods

### Option A: Docker Compose (Recommended)

1. Ensure Docker and Docker Compose are installed.
2. From the project root, launch both services:
   ```bash
   docker compose up --build -d
   ```
3. Check container status:
   ```bash
   docker compose ps
   ```
4. Access the application:
   - Frontend: `http://localhost:3000`
   - Backend API: `http://localhost:8000`
   - API Docs: `http://localhost:8000/docs`

### Option B: Bare-Metal / VM Deployment

#### 1. Backend Setup
```bash
cd backend
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows:
.\.venv\Scripts\activate

pip install -r requirements.txt
python ../scripts/init_db.py
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2
```

#### 2. Frontend Setup
```bash
cd frontend
npm ci
npm run build
npm run start -- -p 3000 -H 0.0.0.0
```

## 4. Healthcheck & Monitoring

The backend exposes an audit-grade health status endpoint:

```http
GET /health
```

**Response Example:**
```json
{
  "status": "ok",
  "service": "finn-api",
  "demo_mode": true,
  "database_connected": true,
  "tables_count": 9,
  "timestamp": "2026-11-01T04:35:05.123456+00:00",
  "version": "1.0.0"
}
```

If database connectivity is lost, `status` returns `"degraded"` and `"database_connected": false`.

## 5. PWA Installation & Validation

FINN is built to install natively on iOS and Android:
- **Manifest**: Located at `/manifest.webmanifest` (generated by Next.js `manifest.ts`).
- **Display**: Standalone without browser chrome.
- **Theme**: Dark fintech `#090e12`.
- **Viewport**: Scaled to device width, mobile safe-area insets respected (`env(safe-area-inset-bottom)`).
- **Zero Horizontal Overflow**: Guaranteed 390px mobile viewport compliance.
